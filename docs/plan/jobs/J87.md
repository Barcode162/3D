# J87 · A real engine, step 2: copies drawn together

**Chapter:** the engine
**Serves:** N5 N3
**From the user:** request `2026-10-25 #5` (the engine a real one; the fixes from Claude's review)
**Verdict:** doable now — the renderer's own code; the world remake (J35, J70-J77) multiplies the things to draw, so this comes first

## Goal
Every copy of the same model (stools, glasses, candles, lamps…) is drawn
in one go instead of one by one: far fewer draw calls per frame, so the
phone has room for the world remake's hundreds of things.

## Where it stands
280 draw calls in the bar's main view (smoke test, 2026-10-25); each placed
model has its own 256-byte slot and its own draws, part by part.

## Design
- Per-copy data (matrix, tint, glow) in an instance buffer (a vertex buffer
  read once per copy), so one `DrawIndexed(…, copies)` draws them all;
  the shaders read it instead of the per-object slot for models.
- Each frame: the visible copies of each model part, grouped (culling stays
  per copy), written in one buffer write; see-through parts still sorted
  back to front (drawn one by one, as now).
- The mirrors and the reflection capture use the same groups.
- The smoke test prints the draw calls; before and after are recorded.

## Pieces
- **J87.1** The instance path: the buffer, the shaders, grouped draws in
  the main view, the mirrors and the capture; the smoke test's draw count.
  *Check:* the bar looks exactly as before; Settings → Performance shows
  fewer draws (or `?perf=1`: the "draws" number drops)

## Done when
Pictures before and after match; the draw count drops; the smoke test passes.

## Risks
A model that changes its look per copy (a highlighted stool) must keep it:
tint and glow travel per copy.
