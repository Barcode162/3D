## Goal
Every copy of the same model (stools, glasses, candles, lamps…) is drawn
in one go instead of one by one: far fewer draw calls per frame, so the
phone has room for the world remake's hundreds of things.

## Where it stands
280 draw calls in the bar's main view (smoke test, 2026-10-25); each placed
model has its own 256-byte slot and its own draws, part by part.

## Research (2026-10-25, rule "Research, then build")
**What it touches** (searched across the repo):

  mirror, the six faces of the reflection capture), `loadModels` (one 256-byte

- Not touched: the plain boxes and avatars (`vs_main`, `vs_skinned`), bounced

- The bar's counts today: 106 placed models from 39 files; the most repeated:

**How it works now:** each copy binds its own uniform slot and draws each of
its parts; big room models are cut into chunks culled one by one.
**How engines do it:** per-instance data in a vertex buffer stepped once per
copy (the classic way; works everywhere), or a storage buffer read by
`instance_index` (Unity's and Unreal's modern path). Safari's limits for
storage buffers in the vertex stage aren't documented (surveys show 8+), so
the vertex-buffer way is the safer one here.
**Traps found:**
- Every pass of a frame is in one command buffer: per-copy data written for
  a mirror and then for the main view must go to **different places** in the
  instance buffer, or the later write wins for every pass.
- See-through copies (glasses) must still be drawn back to front, one by
  one; chunked room models keep their per-chunk culling.
- The highlight and the loops' tint and glow are per copy: they travel in
  the instance data.
- Earlier incidents that apply: search the whole repo for every renamed
  name (2026-10-25-astc-label-renamed); open the bar once before shipping
  (2026-10-25-viewer-never-drew).

## Design
- Per-copy data (the model matrix, tint and own glow, highlight: 96 bytes) in
  an **instance vertex buffer**; `vs_model` reads it as vertex inputs
  (locations 4–9) and hands tint and glow to the fragment stage, so
  `litModel` no longer reads the per-object slot.
- Each frame's draws are grouped by model file and part: all visible copies
  of a part in one `DrawIndexed(…, copies)`. A ring buffer per frame: each
  pass appends its copies at a fresh offset (no pass overwrites another's).
- Chunked parts (room shells) and see-through parts draw one copy at a time
  (instance count 1) through the same path.
- `kMaxModels` 512 → 4096; the ring sized for every pass of a frame.
- `?perf=1` already counts draws; the before/after counts go in this plan.
