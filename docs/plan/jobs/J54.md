# J54 · GitHub's browser tests run to the end (formerly EN4)

**Chapter:** the engine
**Serves:** N5
**From the user:** the approved order (request 2026-10-24 #7); known issue KI-5
**Verdict:** doable now — our own tests and workflows; no cost (a paid machine with a graphics card is parked: J69)

## Goal
Every browser test on GitHub runs to its last check, so a red result always
means something is really broken, never "the machine was too slow to take a
picture".

## Where it stands
Since the new light, GitHub's machine (no graphics card, drawing in
software) times out taking pictures: smoke, multiplayer, 4K Mania, chess and
the arcade stop at their first `page.screenshot` (30–90 s); menus waits 120 s
for its button; after chess and a racing rig the Menu button is under the
game; the two-player race fails from "Bob loaded" (runs 211, 214, 215; KI-5).
The checks before the pictures pass. The tests' own light (J2.1) didn't fix it.

## Design
- **J54.1** Find where the time goes: one GitHub run with a trace around a
  picture (frame time, what's drawing, the page's own work), and the same
  test here; the cause named in KI-5.
- **J54.2** The fix the trace points to (a cheaper frame while a picture is
  taken, pictures that wait for a frame instead of the page, or fewer
  pictures where a check says the same), so every suite runs to the end; no
  check is skipped or weakened.

## Done when
A game deploy on GitHub where every browser test reaches its last check;
the failures left, if any, are real and have their own known issue.

## Risks
Some suites may also fail for real once they get past their pictures: each
then gets its own known issue (never a fake green).
