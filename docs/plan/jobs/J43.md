# J43 · The script language: its realistic scope (J43, J78–J81)

**Chapter:** the engine
**Serves:** N2 (made from scratch: our own language), N3 (a world that's alive)
**From the user:** the North star N2 (our own script language); the restructure's J7.3; formerly T1 ("The bar script language: parser, a tiny safe runner, errors with line numbers in the Studio; five behaviours rewritten as scripts")
**Verdict:** doable now (after the freeze) — a small interpreted language inside our own engine, from scratch in C++; no outside library, no new cost

## Goal
J Production's own language for what things in the world **do**: a candle
that flickers faster when the door opens, a jukebox that picks songs by the
mood, a stool that remembers its regular. Short scripts that read almost like
sentences, that you, Claude or another AI can read and write, and that never
break the bar: a mistake is caught before it runs, with the line and a hint
to fix it.

## What it is (the scope)
- **Small.** Things, their states, the events that move them between states
  (tapped, entered, a timer, a beat of the music, a message from another
  thing), their loops, a few numbers and words they remember, and messages
  to other things. That's all.
- **Safe.** A script only touches its own thing and the messages it sends:
  no files, no network, no other player's data, no money. Each script gets a
  step budget per frame and a memory limit; a script that runs out is paused
  and reported, never freezes the bar.
- **Built on what exists.** Today a thing's life is data: states, rules and
  loops in its kind (`assets/world/kinds/`, [the world model](../../handbook/systems/engine/world-model.md)).
  A script is a readable way to write that data, plus the little logic the
  data can't hold (counting, remembering, choosing). Everything a kind file
  says today can be said as a script, and back.
- **Written for people and AIs.** Plain words, one way to do each thing, no
  symbols to memorise; indentation shows what belongs to what. Every error
  says the line, what's wrong in plain words and a fix hint ("line 4: `tappd`
  isn't an event; did you mean `tapped`?").
- **Not a replacement** for C++ (the engine) or JavaScript (the pages and
  menus). Games like chess or racing stay in code; a script can start them.

A first sketch (the grammar is J43's to settle):

```
thing light switch
  state on
    when tapped: go to dim
  state dim
    when tapped: go to on

thing candle
  remember flickers = 0
  state calm
    play loop sway
    when the door opens: go to flicker
  state flicker
    play loop gust
    add 1 to flickers
    after 2 seconds: go to calm
```

## Not in scope
Making new 3D models from a script, editing the world's layout from a
script, scripts that run on the server (the room decides shared things,
J62), and anything touching accounts, credits or ages.

## Design
The language lives in the engine (`looped/script/`, C++ → WebAssembly, like
the rest of Looped): a parser and checker, then a tiny runner the world
model calls each frame. The Studio edits scripts with their errors shown
where they are. Options not taken: Lua or JavaScript inside the engine (an
outside language: against "from scratch"), and a visual blocks editor (later,
on top of the same language, if you want one).

## The jobs, in order
- **J43** The design on paper: the grammar on one page, 20 scripts written
  for things that exist today (the light switch, the mirror, the candle, the
  jukebox, the darts board, a stool…), and every error with its plain words
  and fix hint. Nothing built; you read the examples on your phone and say
  whether they read well.
- **J78** The parser and checker (C++): every error with its line, column,
  plain words and fix hint; native tests on the 20 examples and on broken
  copies of them.
- **J79** The tiny safe runner: events, states, timers, loops, remembered
  values and messages; the step budget and memory limit; the world model runs
  a thing's script next to its data, and turns a kind's states, rules and
  loops into a script and back without losing anything.
- **J80** Scripts in the Studio: a script for a kind, errors underlined with
  their hint as you type, the change live on the phone.
- **J81** Five behaviours rewritten as scripts (the light switch, the mirror,
  the polished things' knock, the candle, the jukebox), behaving exactly as
  before, the tests proving it.

After these: the light show (J50) and the timeline (J57) use scripts.

## Done when
J81 is live: five things in the bar run on scripts, they behave as before on
your phone, and the Studio shows a broken script's error and hint instead of
breaking the bar.

## Risks
- **Too big a language:** the scope above is the limit; anything more is a
  new job with its own verdict.
- **Phone speed:** a runner on every thing every frame costs time; scripts
  only wake on their events and timers, and the budget caps them.
- **Two ways to say one thing** (kind data and scripts) drifting apart: J79
  converts both ways and a test checks the round trip.
