# J83 · Claude's key, made from Dev

**Chapter:** the tools
**Serves:** N5
**From the user:** request `2026-10-25 #3` (docs/records/requests/), after KI-34
**Verdict:** doable now — the server already makes keys (`hub/hub.php` → `{"a":"key"}`, owner only); only Dev's page is missing its button; keys are an "ask first" (Charter §5) and the user said yes

## Goal
The owner can make a new Claude key from the phone: Dev → People → Claude's
key → Make a new Claude key. The key shows once with a Copy button, and the
page says where it goes (the Claude app's environment settings, `HUB_KEY`,
never the chat).

## Scope
`dev/people.js` (the section, owner only), its Handbook page
(`docs/handbook/ui/dev-people.md`), the Dev test if it covers People.
**Not in scope:** `hub/hub.php` (unchanged), where the key is stored, the
environment's settings (the user's).

## Design
- Drawn under the people list, only when the signed-in person is the owner
  (the same check as "Make admin").
- One tap asks first ("This replaces the old key…"), then posts
  `{"a":"key"}` to `/hub/hub.php` with the login token (Dev's `D.post`).
- The key goes into a read-only field with Copy; it is never logged, stored
  in the page or sent anywhere else. Reloading the page hides it.
- In Dev's demo mode the button says so instead of making a key.

## Pieces
- **J83.1** Dev → People: Claude's key section, owner only. *Check:* Dev →
  People, scroll down: "Claude's key" with "Make a new Claude key"; tap it,
  say yes: the key shows with Copy.

## Done when
The Dev checks pass, the build is live, and the user makes a key from the
phone, puts it in the environment as `HUB_KEY`, and a new session's store
push works (KI-34 closes then).

## Risks
- A key made by mistake replaces the working one: the button asks first.
