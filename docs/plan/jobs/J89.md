## Goal
A login can't be guessed by brute force, an old login expires, two saves
at the same moment can't undo each other.

## Where it stands (Claude's review, 2026-10-25)
Passwords are bcrypt hashes (good), but tokens never expire, guessing is
only slowed by a 0.4 s pause (many guesses at once aren't stopped), and a
profile's file is read, changed and written with no lock.

## Design
- Tokens: a login unused for 90 days stops working (its file's last use
  is kept, refreshed at most once a day).
- Guessing: per username and per address, 10 wrong passwords (or recovery
  codes) within 15 minutes lock that door for 15 minutes ("Too many tries:
  wait 15 minutes").
- Locks: every read-change-write of a user's file under a lock on it.

## Pieces
- **J89.1** Expiring logins, the guessing limit and the locks; the accounts
  tests cover each. *Check:* log in on the phone as usual: nothing changes
  for you; ten wrong passwords in a row say "Too many tries"

## Done when
The accounts tests pass with the new cases (expiry, the limit, two saves at
once).

## Risks
Shared hosting's file locks: flock works on IONOS (names.json already uses
it).
