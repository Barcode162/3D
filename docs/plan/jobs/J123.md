### Why it's grainy (Loop3D, read in the code)
1. **Film grain is on by default.** 8 of the 12 film looks add grain (`engine/render/scene.cpp`, `lookByName`:
   blockbuster 0.015, noir 0.05, bleach 0.03, seventies 0.06, neon 0.02, documentary 0.02, horror 0.045,
   western 0.035), and 15 of the 29 scene files add more on top (`grain: 0.02`–`0.05`).
2. **It is re-rolled every frame**: `engine/gpu/shaders.h` `fsPost` seeds it with the time (`post.fx2.y * 60`),
   so it fizzes 60 times a second instead of sitting still like film.
3. **It is drawn at 1 pixel per screen point on Phone** (`renderer.cpp` caps the canvas at `maxRatio_` = 1×), so on
   the iPhone's 3× screen each grain dot is 3 × 3 real pixels, and automatic resolution starts at 87 % and drops
   to 50 % before that: big, soft, dancing dots.
4. **Bumps from patterns use screen-space differences** (`dpdx`/`dpdy` of a procedural height in `shade`): 2 × 2
   pixel blocks and sparkling highlights while moving; nothing smooths shading between frames.
5. **Ultra shows one path-traced sample per frame**: noisy whenever anything moves.
6. The bar (3D's engine) has the same root: light beams and soft shade start each pixel at a noise value turned
   every frame (`looped/shaders/scene.wgsl` `fs_beams`, `ssao.wgsl`) and **no engine of ours averages frames**.
   Every big engine pairs per-frame noise with a temporal filter (TAA, Unreal's TSR); without one, the noise is
   shown raw.

### Why it lags (Loop3D, read in the code)
1. **Nothing off-screen is skipped**: no frustum culling anywhere in `engine/gpu/renderer.cpp`; every thing is
   drawn every frame, twice (sun shadow map and scene).
2. **Back faces are drawn too**: every pipeline sets `cullMode = None`.
3. **Every lamp lights every pixel**: the shader loops over all lamps (up to 256) for every pixel it shades; Ardane
   scenes have 15–22 lamps. Big engines only add the lamps that reach each part of the screen (clustered lights).
4. **Wood, stone and brick are calculated per pixel, every frame**: 5-octave noise (40 hashes per call) in the
   fragment shader instead of textures made once.
5. **No depth pre-pass** and 4× multisampling on a 16-bit colour target on Phone: overdraw shades the same
   pixel several times, and the targets are heavy.
6. The processor is not the problem: a whole scene's script runs 10 seconds in under 0.1 s natively (measured
   here: `loop run`, market 302 things, battle 451, undercity 526).

### What the big engines have that we don't
| They have | Unreal / Unity / Godot | Us |
|---|---|---|
| A project file and a project folder | `.uproject`, Unity's ProjectSettings, `project.godot` | Loop3D's `project.json` (a list of scenes) |
| An import step that bakes assets for the device | cooked `.uasset`, Godot's `.import` | shapes are code; patterns computed live |
| One packed file per game, loaded and unloaded | `.pak`, `.pck` | none |
| A temporal filter (smooth, sharp, noise-free) | TSR / TAA / FSR | none |
| Culling, levels of detail, clustered lights | all three | none in Loop3D (clusters exist only in 3D's new engine) |
| Timing per pass on the target device | GPU profilers | Loop3D: none; frame times only |

## Design (proposed; the user chooses)
**The project file** (name of the extension: the user's choice; `.looped` proposed):
```
my_game/
  my_game.looped      the project file: small, readable text (title, engine version, start, scenes, settings)
  scenes/*.loop       the script
  models/ sounds/ music/ textures/
  .made/              made by the engine, never by hand
```
`loop pack my_game.looped` makes one file to play (scripts compiled, models cut for the phone, textures
compressed, sounds); the player loads it, plays, frees all of it and loads another (purpose 1).
`loop new --template story` makes a project from a template; the AI reads the template, `loop words json` and the
guide, writes the files; `loop check` names every mistake with its line and fix; repeat until clean (purpose 2).

## Pieces (proposed, in order; one commit each, each with its phone check and a benchmark before and after)
- **J123.1** A clean picture: no live film grain (grain only in cinema stills), nothing re-rolled per frame, the
  scenes' `grain:` kept for stills. *Check:* any scene on the phone: the picture stops fizzing.
- **J123.2** Measured on the phone: a baseline benchmark of three scenes on the user's iPhone, and the cost of each
  pass (GPU timing where Safari gives it, else turning passes off one by one). *Check:* the numbers on the tracker.
- **J123.3** Draw less: skip what's off-screen (scene and shadow), back faces off, the sun's shadow redrawn only when
  something in it moves. *Check:* smoother in the big Ardane scenes.
- **J123.4** Light less: each pixel adds only the lamps that reach it; patterns made once into textures.
  *Check:* the market and the undercity smooth at Phone.
- **J123.5** The temporal filter: fewer pixels drawn, averaged over frames with motion, sharp and still.
  *Check:* sharper than today and no shimmer, at the same speed or better.
- **J123.6** The project file and the pack: load and unload at will. *Check:* switch between Samples and Ardane
  from the menu; memory stays flat.
- **J123.7** Templates and the AI loop. *Check:* a new project made from a template plays.
- **J123.8** Shrink (structure: the user decides each step): one engine repo, one language, Bar3D brought over as
  a Loop3D project later, the live bar untouched until then; a one-page rulebook for Loop3D.
