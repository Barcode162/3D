# J60 · Everything off IONOS

**Chapter:** the backbone
**Serves:** N4 N1
**From the user:** request `2026-10-25 #7` ("get everything off ionos and switched over 1st"); earlier, the old board: "Let's get everything out of ionos besides the things that would be security benefits do your thing" (now: everything)
**Verdict:** doable at a cost — strong password hashes need more computing per login than Cloudflare's free plan allows (10 ms per request), so the logins need Workers Paid ($5 a month, the user's call); the address switch is two changes only the user can make (IONOS and Cloudflare dashboards); J89's protections are built into the new logins

## Goal
joshuavelasco.com, the bar, Dev, the Studio, News, sign-in and every store
run on Cloudflare, where the room and the ledger already are. IONOS holds
nothing the project needs; the user decides when to cancel it.

## Where it stands
On IONOS (PHP, SFTP deploys): the site's pages (`homepage/`, `news/`), the
bar's files and its door (`server/gate.php`), accounts (`server/account.php`,
bcrypt hashes, JSON files), the world store (`studio/api.php`), the UI
store (`toolbelt/ui-editor/api.php`), Dev's store (`dev/api.php`), the hub
(`hub/hub.php`: news, pictures, Claude's key), phone reports
(`server/report.php`), the relay (`server/relay.php`), `/classic/`.
About 2,900 lines of PHP. The room asks IONOS who a login belongs to and
which world is live.

## Design
- **One Worker for everything** (the room's, `cloud/`): the bar's and the
  site's files as its static assets, the services as its routes, the data
  in Durable Objects with SQLite (like the ledger): Accounts, Stores
  (world, UI, Dev, hub, reports, versioned as today). Pictures as rows (no
  R2: it needs a card on file).
- **The same addresses and replies**: `/bar/account.php`, `/studio/api.php`…
  keep answering at the same paths with the same JSON, so the game, the
  Studio, Dev and the tools change only where they must.
- **Logins**: every account copied with its bcrypt hash; on its first login
  the password is checked against the old hash (bcrypt written here, from
  scratch, with the standard test vectors) and kept from then on as a
  PBKDF2-SHA-256 hash (600,000 rounds, WebCrypto). J89's protections:
  a login unused for 90 days expires; 10 wrong tries in 15 minutes lock
  that name and address for 15 minutes; saves of one profile one at a time
  (a Durable Object runs one request at a time).
- **The PHP pages** (home, projects, news, sign-in, portal, play, vision,
  engine) become pages the Worker builds from the same templates.
- **Threads**: the Worker sends the headers IONOS couldn't (cross-origin
  isolation), so SharedArrayBuffer becomes possible later.
- **The copy**: one tool (`tools/move_ionos.mjs`) reads every store over
  SFTP and writes it to Cloudflare, checks counts and hashes, and can run
  again (the newest wins) until the switch.
- **The switch**: the user adds joshuavelasco.com to Cloudflare (free) and
  puts Cloudflare's two nameservers in at IONOS; every DNS record
  (including mail, if any) is copied first. The domain's registration can
  stay at IONOS (it only pays for the name) or move to Cloudflare later:
  the user's call.

## Done when
The accounts, room, ledger, site and game tests pass against Cloudflare;
the copy's counts match; joshuavelasco.com loads from Cloudflare on the
user's phone and their login works.

## Risks
- A login that never comes back keeps its bcrypt hash: it still works,
  checked the old way.
- Mail at the domain: if IONOS hosts mail, its records are copied before
  the switch, or mail stops.
- DNS takes up to a day to reach everyone; IONOS keeps serving until the
  copy is final, so nothing is lost meanwhile (writes are frozen for the
  minutes of the final copy).
- The free plan's limits (100,000 requests a day) are fine today; Workers
  Paid lifts them too.
