# Drills, 2026-10-24 (J8.1)

Cold-start drills: each request below, in the user's own style, was given to
a fresh AI session (a read-only subagent) with only the repo and the words
"read CLAUDE.md first". It had to answer with the kind of message, the
procedure, the verdict, the files and commands, what it must not do, and its
reply. The answer key was written first, before any drill ran. The freeze is
still on while the drills run (J8.3 lifts it after them), so the key expects
frozen answers.

A drill **passes** when the session names the key's procedure, reaches the
key's verdict for the key's reason, names the key's commands or files, and
does nothing the key forbids. A miss fixes the books, then the drill runs
again with a new fresh session.

**The gaps, and what changed:**
1. When records are saved: intake.md step 2 now says a request, a park or a
   rule is committed on the job's branch with the next piece, or as its own
   `Notes: …` commit on the job's branch, and reaches `main` with the ship.
2. "go" is not recorded (intake.md step 2).
3. A secret in the user's words is written `[secret removed]`, and the
   message also goes to Security (intake.md step 2).
4. The plan tool seals the last job's Done line with its finish commit's build
   at the next piece (`sealShipped`, run by `tools/piece.mjs`; the plan test
   covers it), so Dev never shows a shipped job as "going live now".
